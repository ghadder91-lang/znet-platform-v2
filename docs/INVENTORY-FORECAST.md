# توقع المخزون وسياسة مخزون الأمان — 1.3

افتح الشبكة ← توقع المخزون. هذه مرحلة المراقبة والتوصيات من إدارة المخزون الآلية، وليست تنفيذ توليد كروت عبر MikroTik. لا يتصل هذا المحرك بأي جهة خارجية ولا يبيع أو ينشئ كروتًا ولا يعدّل القيود المالية.

## الحساب

- المخزون: الكروت المتاحة للبيع فقط؛ تستبعد المباعة والموقوفة.
- المبيعات: الطلبات المدفوعة التي خُصص لها كرت، حسب paid_at؛ لا تشمل المعلقة أو الاستثنائية.
- النافذة: آخر 7 أيام مكتملة بتوقيت اليمن UTC+3؛ للفئات الجديدة تبدأ من أول منتصف ليل بعد إنشائها، أو لحظة الإنشاء إذا كانت منتصف الليل بالضبط. اليوم الجاري خارج المتوسط. الأيام الصفرية داخلة في القاسم.
- شرط عرض التوقع: 3 أيام مكتملة وخمس مبيعات على الأقل. غير ذلك لا يُعرض متوسط أو موعد نفاد، ويظل نفاد المخزون وحد التنبيه الثابت ظاهرين.
- المتوسط = المبيعات / أيام النافذة. التغطية بالساعات = المتاح / المتوسط × 24.
- الهدف = تقريب (المبيعات × أيام التغطية المستهدفة / أيام النافذة) إلى الأعلى.
- الاحتياج = أكبر قيمة بين صفر و(الهدف − المتاح).
- التوصية = أصغر قيمة بين الاحتياج، أقصى كمية للتوصية الواحدة، والمساحة المتبقية تحت سقف المخزون؛ ولا تقل عن صفر.

مثال: 490 كرتًا خلال سبعة أيام، ومخزون 110: المتوسط 70 يوميًا والتغطية نحو 37.7 ساعة. سياسة يومين تتطلب 140 كرتًا؛ المقترح 30. إذا كان حد التوصية 10، يعرض 10 مع تحذير أن الحد يمنع بلوغ الهدف.

هذا متوسط تاريخي قابل للتفسير، وليس نموذج ذكاء اصطناعي مدربًا أو ضمانًا. لا يقيس ساعات الانقطاع أو المخزون التاريخي؛ نفاد المخزون أو غياب التحصيل قد يخفض المتوسط دون أن يعكس الطلب الحقيقي. لا يدعم موسمية الأعياد أو التصحيح اليدوي للمبيعات أو توقع مبيعات التطبيق الخارجي. بيانات مختبر الدفع معزولة ولا تدخل الحساب.

## السياسات والحدود

السياسة مستقلة لكل فئة: تغطية 1–14 يومًا، سقف مخزون 1–100000، حد توصية 1–10000 لا يتجاوز السقف. الافتراضي غير محفوظ والمراقبة معطلة. يتطلب الحفظ رقم النسخة الحالي، ويحفظ تغيير السياسة في سجل النشاط. الحدود تخص الاقتراحات فقط ولا تفرض سقفًا على الاستيراد اليدوي.

يمكن تقييم سياسة محفوظة يدويًا حتى إذا كانت المراقبة الدورية متوقفة. تكرار التقييم لنفس إصدار السياسة خلال 15 دقيقة يعيد آخر نتيجة محفوظة. تغيير السياسة ينشئ نسخة جديدة قابلة للتقييم فورًا. الواجهة تعرض قراءة حية عند فتح الصفحة أو التحديث، والسجل يعرض لقطات سابقة قد تختلف عنها.

## التشغيل المستقل

خدمة `forecast-worker` مضافة إلى compose.yaml، وتستخدم قاعدة المنصة الأساسية. عند التثبيت المعتاد:

```sh
docker compose up -d --build
docker compose logs --tail=50 forecast-worker
```

للتشغيل المباشر على Node 24 من جذر المشروع بعد إعداد البيئة:

```sh
node --env-file=.env scripts/forecast-worker.mjs
# دورة واحدة للتحقق:
node --env-file=.env scripts/forecast-worker.mjs --once
```

تفحص الخدمة كل دقيقة حتى 100 سياسة مستحقة، وتعيد تقييم السياسة كل 15 دقيقة تقريبًا. تعمل تلقائيًا للشبكات المعتمدة والسياسات المفعلة فقط. التوقف أو كثرة السياسات يؤخران التقييم؛ لا تعتبر الواجهة مجرد تفعيل الخيار إثباتًا أن الخدمة تعمل. تحقق من أوقات آخر التقييمات ومن سجلات الخدمة. بعد إعادة التشغيل تعالج السياسات المستحقة دون إعادة إنشاء كل الفترات الفائتة.

المطالبة والتقييم وحفظ الوقت التالي تتم ضمن معاملة واحدة. اختُبر تشغيل عمليتين مستقلتين على قاعدة SQLite واحدة دون تكرار التقييم. يحتفظ النظام بآخر 100 تقييم لكل فئة، ويعرض آخر خمسة. سجل تغيير السياسات منفصل ولا يُحذف بهذا الحد. لا توجد رسائل SMS أو تنبيهات خارجية لهذا المحرك بعد؛ النتائج متاحة في صفحة توقع المخزون.

## حدود التحقق

اجتازت النسخة 40 اختبارًا آليًا، وبناء Next، واختبار HTTP للحفظ والتقييم والتعارض ومنع الطلبات غير المصرح بها. لم يُختبر Docker فعليًا في هذه البيئة. تعذر اختبار المتصفح لأن Chromium غير مثبت؛ يلزم فحص بصري على الهاتف قبل اعتماد الإصدار للتشغيل العام. قاعدة واحدة وخادم واحد؛ لا يدّعي هذا الإصدار دعم عشرات آلاف الشبكات دون اختبارات حمل وتطوير بنية النشر.
