# عقد ربط زد نت 1.1 — مختبر فقط

هذه مواصفات API التي بنيناها لزد نت، وليست وثائق الكريمي أو شلن. جميع المسارات أدناه تخص قاعدة الاختبار المنفصلة. لا توجد بوابة تحصيل أو SMS حقيقية مفعّلة.

## الإعداد

`SANDBOX_ENABLED=true` يفعّل المختبر. `SANDBOX_DATABASE_PATH` يحدد قاعدة الاختبار؛ افتراضيًا data/sandbox.sqlite، ويُرفض مسار قاعدة التشغيل نفسها.
بيانات دخول الشريك التجريبية تُعرض لمسؤول الخادم فقط:

```sh
docker compose exec app node scripts/sandbox-credentials.mjs
```

لا تنشر apiKey أو webhookSecret في المتصفح. هذه مفاتيح مختبر وليست مفاتيح محافظ. لا تغيّر مفتاح تشفير المخزون لتدويرها؛ تدوير مفاتيح الإنتاج يحتاج تصميمًا منفصلًا.

## إنشاء الطلب

`POST /api/partners/sandbox/orders`

التوثيق: `Authorization: Bearer <apiKey>`، وصيغة الجسم application/json.

```json
{"networkId":"sandbox-network-id","categoryId":"sandbox-category-id","requestKey":"unique-request-0001","customerRef":"customer-0001","phone":"+967770000000"}
```

أنشئ الشبكة والفئة الوهميتين من «مختبر الربط»؛ يمكن لمسؤول الخادم قراءة معرفاتهما من قاعدة المختبر. requestKey بطول 16–80 حرفًا، وcustomerRef بطول 8–120. نفس مفتاح الطلب مع نفس المدخلات يعيد الطلب نفسه. تغيير الفئة أو العميل أو الهاتف مع إعادة المفتاح ينتج 409. السعر من الخادم، والعمولة التجريبية 5% وليست اتفاقًا ماليًا ملزمًا.

الاستجابة: orderId، amount (ريال يمني صحيح)، currency=YER، status، expiresAt بالميلي ثانية، mode=sandbox.
مهلة الطلب 15 دقيقة. يُخصص الكرت عند الدفع، ولا يحجز عند إنشاء الطلب. نفاد المخزون وقت الدفع يؤدي إلى مبلغ معلق وحادثة؛ يجب اعتماد استراتيجية الحجز قبل الإنتاج.

## إشعار الدفع

`POST /api/partners/sandbox/payments`

```json
{"eventId":"evt-0001","paymentId":"pay-0001","type":"payment.succeeded","merchantId":"znet-sandbox","orderId":"order-id","customerRef":"customer-0001","amount":500,"currency":"YER"}
```

- X-ZNET-Timestamp: وقت UNIX بالثواني؛ السماح ±300 ثانية.
- X-ZNET-Signature: HMAC-SHA256 بصيغة hex صغيرة باستخدام webhookSecret كنص UTF-8 على `timestamp + "." + raw_body`.
- لا تعِد ترتيب JSON أو تعديل مسافاته بعد التوقيع. حد الجسم 8192 بايت.
- يجب ضبط ساعة الخادم. الدالة signEvent في server/partner-protocol.mjs مرجع التنفيذ.

200 مع outcome=paid يعني تخصيص الكرت وقيد العملية وإنشاء مهمتي التسليم ذريًا. 200 مع outcome=exception يعني حفظ مبلغ معلق وحادثة دون كرت جديد، ولا يعني تسليمًا ناجحًا. replayed=true يعني تجاهل تكرار مرجع الدفع.
401 للتوقيع غير الصحيح/القديم، و409 لتعارض معرف الحدث أو الدفع، و400 للبيانات غير المقبولة، و404 لطلب أو عميل أو مزود غير مطابق.
أعد المحاولة بنفس الجسم ومعرفي الحدث والدفع وتوقيع بوقت جديد؛ لا تنشئ مرجع دفع جديدًا للإشعار نفسه.

## نتيجة المحفظة وإقرار الاستلام

`POST /api/partners/sandbox/result` مع Bearer الخاص بالشريك:

```json
{"orderId":"order-id","customerRef":"customer-0001"}
```

delivery=not_ready قبل الجاهزية. عند الجاهزية يرجع username وpassword للكرت نفسه في كل قراءة، دون بيع جديد. النتيجة لا تُخزن مؤقتًا، والقراءة مسجلة في التدقيق.
على المحفظة التحقق من ارتباط جلسة العميل بـcustomerRef؛ المرجع ليس كلمة سر.

بعد العرض والاستلام، استخدم `POST /api/partners/sandbox/ack` بالجسم والتوثيق نفسيهما. يتحول وضع القناة من available إلى delivered. الإقرار قابل للتكرار بأمان.

## قناة SMS

المحاكي لا يتصل ببوابة رسائل ولا يرسل إلى الهاتف. delivered في المختبر تعني نجاح محاكاة الاستلام فقط.
واجهة المحول المستقبلي:

```js
await smsAdapter.send({idempotencyKey,orderId,provider,customerRef,phone,username,password});
// بعد إيصال استلام موثوق: {status:'delivered',receiptId:'...'}
```

HTTP 200 من بوابة SMS لا يكفي لإثبات الاستلام. يحتاج المحول الحقيقي منع تكرار الإرسال وإيصالات أو استعلام حالة ومعالجة مهلة الاتصال. لا يمكن ضمان عدم تكرار الرسالة عبر بوابة لا تدعم ذلك. لا يوجد محول إنتاجي في هذه الحزمة.

## المهام وإعادة المحاولة

لكل قناة مهمة ومعرف ثابت يُستخدم في كل محاولة. حد المحاولات 5؛ الانتظار 30 ثم 60 ثم 120 ثم 240 ثانية. حجز المهمة 60 ثانية ويستعاد بعد تعطل العامل. بعد الحد تتوقف المهمة وتفتح حادثة. إعادة التسليم لا تخصص كرتًا آخر.

خدمة delivery-worker في compose تشغّل المختبر فقط كل خمس ثوانٍ. لتنفيذ دورة واحدة:

```sh
docker compose exec app node scripts/delivery-worker.mjs --once
```

## ما يلزم للإنتاج

وثائق المزودين، محولات وتوقيعات حقيقية، أسرار مستقلة قابلة للتدوير، صلاحيات الشريك للشبكات، حجز المخزون، إيصالات SMS، المطابقة والاسترداد والسحب والتسويات، واختبار الحمل والأمان. تغيير اسم sandbox لا يحقق ربطًا حقيقيًا.
