# مركز القيادة والتحكم بالشبكات — 1.5

## دخول المدير

أنشئ حساب المدير من الخادم باستخدام الأداة المرفقة؛ التسجيل العام ينشئ صاحب شبكة فقط:

```sh
docker compose exec app node scripts/admin.mjs admin@example.com
```

استبدل البريد ببريد المدير. تظهر بيانات الدخول ورمز الاستعادة مرة واحدة؛ احفظهما بطريقة آمنة. تسجل الدخول من صفحة الدخول المعتادة وتختار «مركز القيادة». الأداة ترفض استبدال حساب موجود. راجع README للتثبيت والنسخ الاحتياطي. لا يوجد حساب افتراضي أو كلمة مرور مشتركة في الحزمة.

## ما تعرضه اللوحة

- الشبكات المسجلة، المعتمدة غير المعلقة، الطلبات المنتظرة والمعلقة تشغيليًا.
- إجمالي الكروت المتاحة والحوادث المفتوحة وفروقات المطابقة غير المراجعة.
- عدد وقيمة الكروت المباعة من الطلبات المدفوعة خلال آخر 24 ساعة؛ هذا مقياس مبيعات، لا إثبات تسوية بنكية.
- عدد اتصالات MikroTik المعدة وعدد فحوصاتها الناجحة خلال 15 دقيقة. الاتصال يُفحص يدويًا؛ لا يُستنتج تعطل راوتر من غياب فحص حديث.
- بحث بالاسم أو UUID أو الهاتف أو بريد المالك، وتصفية بالمحافظة والاعتماد والتعليق. النتائج 25 لكل صفحة. المؤشرات الإجمالية لجميع الشبكات ولا تتغير بتصفية القائمة.
- تفاصيل شبكة: حساب المالك، الفئات والمخزون، مجاميع القيود، آخر 20 طلبًا، آخر 20 حادثة مفتوحة، آخر 20 إجراء تحكم وآخر 30 نشاطًا.

تعرض اللوحة قاعدة المنصة الأساسية فقط. مختبر الدفع له قاعدة منفصلة لا تدخل بياناته التجريبية في المؤشرات. لا تُرجع لوحة الإدارة أسرار الراوتر أو محتوى الكروت أو كلمات المرور. صلاحية المدير تُتحقق من قاعدة الحسابات في كل طلب، وليس من عنوان البريد أو حقول يرسلها المتصفح.

## اعتماد الشبكة وتعليقها

اعتماد التسجيل إجراء مستقل في صفحة مراجعة الطلبات. التعليق التشغيلي لا يغير قرار الاعتماد. رفع التعليق عن شبكة مرفوضة أو قيد المراجعة لا يجعلها معتمدة.

عند «تعليق» يفتح تأكيد يوضح الأثر، ويتطلب سببًا من 10 إلى 1000 حرف. يظهر السبب للمالك. يحفظ النظام وقت القرار وهوية المدير ورقم نسخة متزايد في سجل لا يسمح التطبيق أو مشغلات SQL بتعديله أو حذفه. مدير قاعدة البيانات ذي الصلاحيات الكاملة يستطيع تغيير بنية SQLite، لذا يلزم ضبط وصول الخادم؛ السجل ليس مخزن تدقيق خارجيًا غير قابل للعبث.

الأثر الفعلي للتعليق:

1. يمنع إنشاء طلب بيع جديد في محرك الطلبات.
2. إذا وصلت دفعة موثقة لطلب سابق أثناء التعليق، يسجلها المحرك بقيد متوازن في حساب الدفعات المعلقة، ويفتح حادثة. لا يخصّص كرتًا لهذه الدفعة.
3. يوقف التقييمات الدورية لسياسات المخزون؛ تبقى السياسات محفوظة، والقراءة والتقييم اليدوي متاحين.
4. يبقى صاحب الشبكة قادرًا على الدخول ومراجعة بياناته ومخزونه وإعداداته. لا تمحو تعديلات بيانات الشبكة التعليق.
5. لا يقطع إنترنت MikroTik، ولا يغيّر إعداداته، ولا يحذف أو يعطّل الكروت الموجودة عليه. تسليم الطلبات المدفوعة والمخصصة قبل التعليق يبقى مستقلًا عن هذا القرار.

«إعادة التشغيل» تتطلب سببًا ورقم النسخة الحالي. تعيد إتاحة عمليات المنصة للشبكة المعتمدة عندما تكون التكاملات اللازمة مفعلة. لا تسوي الحسابات أو تسترد الدفعات ولا تعيد بيع الطلبات الاستثنائية تلقائيًا. إعادة الإشعار نفسه بعد الاستئناف تعيد النتيجة السابقة دون تخصيص كرت ثانٍ أو قيد جديد.

إذا عدل مدير آخر الحالة، يرفض النظام القرار المبني على نسخة قديمة. أغلق نافذة القرار وحدّث البيانات ثم راجع الحالة قبل إعادة القرار. القرارات لا ترسل SMS أو بريدًا للمالك؛ تظهر في واجهته وسجل نشاطه.

## التشغيل والحدود

خذ نسخة احتياطية ومفتاحها قبل الترقية، واحتفظ بملف البيئة وقاعدة البيانات. الترحيل 0010 يضيف التحكم التشغيلي دون مسح البيانات. الحوادث هنا للعرض؛ لم تضف أدوات إغلاق الحوادث المالية أو تعديل الأرصدة أو السحب/الاسترداد. لا يوجد انتحال حساب المالك أو تصدير أسرار الكروت من مركز القيادة.

اختُبرت صلاحيات الإدارة، البحث والتقسيم، تضارب نسخ القرارات، حماية سجل التحكم، أثر التعليق على الدفع والمراقبة، ومنع إزالة التعليق بتعديل المالك. اختُبرت HTTP بحسابي مالك ومدير منفصلين. لم يُنجز اختبار المتصفح أو Docker أو تحميل إنتاجي كبير في هذه البيئة. لا توجد مبيعات حقيقية مفعلة حتى اكتمال ربط المزود واختباره ميدانيًا.
