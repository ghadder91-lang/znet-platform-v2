# زد نت — النسخة المستقلة 1.5 (تشغيل تجريبي)

هذه نسخة مستقلة عن ChatGPT وSites لتشغيل الحسابات والشبكات والمخزون على خادم Linux واحد. **ليست اكتمالًا لجميع وظائف المنصة التجارية المقترحة.** لا يوجد ربط دفع أو SMS حقيقي مفعّل. أضيف موصل MikroTik للقراءة، ويحتاج إعداد خادم وراوتر واختبارًا ميدانيًا قبل اعتماده.

## التثبيت على خادم

1. خادم Linux مع Docker Engine وDocker Compose، ونطاق تملكه يشير إلى عنوان الخادم. افتح 80 و443 فقط للويب. لا تعرض منفذ التطبيق 3000 للعامة.
2. فك الحزمة في `/opt/znet` أو مجلد تختاره. ادخل ذلك المجلد.
3. باستخدام Node.js 24:

```sh
node scripts/init.mjs platform.example.com
```

استبدل النطاق بالنطاق الحقيقي. ينشئ هذا الأمر `.env` بمفتاح تشفير عشوائي، ويرفض استبداله إن كان موجودًا. لا تستخدم قيم الملف `.env.example` حرفيًا.

إذا كان المتاح Docker فقط، يمكنك استخدام:

```sh
docker run --rm -v "$PWD:/app" -w /app node:24-bookworm-slim node scripts/init.mjs platform.example.com
```

4. احتفظ بنسخة مشفرة خارج الخادم من `.env`، منفصلة عن النسخ الاحتياطية للبيانات. ضياع المفتاح يعني ضياع القدرة على فك تشفير الكروت.
5. ابْنِ وشغّل:

```sh
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 app
```

يسحب البناء الاعتماديات من الإنترنت. تم الحفاظ على قفل الاعتماديات. لم تُجرَّب عملية تنزيل نظيفة أو حاوية Docker في بيئة التسليم؛ اختبرها على خادم تجريبي قبل نشرها للعملاء.

6. أنشئ حساب المدير من وحدة الخادم:

```sh
docker compose exec app node scripts/admin.mjs owner@example.com
```

يعرض كلمة مرور عشوائية ورمز استعادة مرة واحدة. خزنهما في مدير كلمات مرور. لا يعيد الأمر تعيين حساب موجود ولا يمنح أول مسجل صلاحية المدير.

7. افتح نطاقك عبر HTTPS وسجل الدخول. يمكن لصاحب الشبكة إنشاء حساب من صفحة الدخول. البريد معرف دخول فقط وغير موثق بالرسائل حاليًا. لحظر التسجيل الجديد، اضبط `ALLOW_REGISTRATION=false` في `.env` وأعد إنشاء خدمة التطبيق:

```sh
docker compose up -d --force-recreate app
```

لا تطلب كلمات مرور أصحاب الشبكات ولا تمنح صلاحيات بمجرد تطابق البريد مع بريد مكتوب في واجهة العميل.

## التخزين والنسخ الاحتياطي

SQLite تحفظ البيانات في volume باسم `znet_data` حسب اسم مشروع Compose. النسخة لخادم واحد وعملية تطبيق واحدة؛ لا تستخدم replicas متعددة ولا ملف SQLite على مشاركة NFS. لم تُختبر أحمال آلاف الشبكات. الانتقال إلى PostgreSQL وعمال منفصلين يتطلب تطويرًا واختبارًا مستقلين.

إنشاء نسخة متسقة أثناء التشغيل:

```sh
docker compose exec -T app node scripts/backup.mjs
docker compose cp app:/app/backups ./backups-local
```

كل مجلد نسخة يتضمن `znet.sqlite` و`manifest.json`. انقل النسخة خارج الخادم، واحتفظ بالمفتاح الأصلي منفصلًا. لا تنشر النسخ على رابط عام. يمكن جدولة الأمر عبر cron على الخادم؛ لا توجد جدولة مفعلة تلقائيًا في الحزمة.

### استعادة بعد تعطل الخادم

الأفضل الاستعادة على تثبيت جديد بقاعدة فارغة:

1. استخدم `.env` الأصلي، وأوقف التطبيق والعاملين حتى لا تبقى اتصالات أو كتابات أثناء الاستعادة.
2. ضع مجلد النسخة على الخادم في `restore-input`.
3. نفذ:

```sh
docker compose stop app delivery-worker forecast-worker
docker compose run --rm --no-deps -v "$PWD/restore-input:/restore:ro" app node scripts/restore.mjs /restore
docker compose up -d app delivery-worker forecast-worker
```

يرفض الأمر استبدال قاعدة موجودة، أو نسخة تالفة، أو مفتاح غير مطابق. إن كانت قاعدة قديمة موجودة، احتفظ بها ومرفقاتها WAL/SHM في مكان آمن قبل تجهيز volume جديد؛ لا تحذف بيانات إنتاج لتجربة الاستعادة. لا تستخدم `docker compose down -v` على إنتاج لأن ذلك يحذف volumes.

## التطوير والاختبار خارج Docker

Node.js 24 وpnpm 11.25.0:

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm build
```

للتطوير، حمّل الإعدادات من `.env`، واجعل `APP_ORIGIN=http://127.0.0.1:3000`، وحدد `DATABASE_PATH=./data/znet.sqlite`. ثم `pnpm dev`. Next يقرأ `.env`، أما أوامر Node المباشرة محليًا فيمكن تشغيلها بـ `node --env-file=.env scripts/backup.mjs`.

## متطلبات الربط الحقيقي

لا يوجد endpoint إنتاجي يقبل من المتصفح ادعاء «الدفع نجح». المختبر فقط يحاكي الدفع على قاعدة منفصلة. دالة `recordVerifiedPayment` داخل `server/commerce.mjs` مخصصة لمحول مزود يتحقق أولًا من التوقيع والعملة والمستفيد وحالة المعاملة. يجب استكمال:

- وثائق الكريمي وشلن الرسمية، حساب اختبار وبيانات وصول آمنة وآلية التحقق من callbacks.
- سياسة العمولة والتسويات المتفق عليها؛ تحفظ العمولة لكل طلب، و500 نقطة أساس في الاختبارات تعني 5% لا إعدادًا تجاريًا ملزمًا.
- قناة شراء وواجهة عميل، حجز مخزون مناسب لزمن الدفع، وتسليم الكرت وتتبع استلامه وإعادة المحاولة.
- المطابقة مع كشف المزود والاسترداد والسحب. المبالغ غير المطابقة تُقيد في حساب تعليق ولا تُسوّى تلقائيًا.
- مزود OTP/SMS وبيئة MikroTik اختبارية وتفويض وصلاحيات محدودة.

المبالغ في المحرك أعداد صحيحة بالريال اليمني؛ العمولات تُقرب لأسفل إلى ريال. يجب اعتماد هذه القاعدة تجاريًا قبل الربط.

## ترحيل بيانات الموقع القديم

الحزمة لا تشمل بيانات أو أسرار الموقع الموجود على Sites. قاعدة جديدة تبدأ فارغة. نقل بياناته يحتاج تصديرًا مع المفتاح الأصلي ومطابقة موثوقة بين مالكي الشبكات وحساباتهم الجديدة. لا تُمنح ملكية شبكة بمجرد كتابة بريدها.

## هيكل المشروع

- `app/`: الواجهات ومسارات HTTP.
- `server/auth.mjs`: تجزئة scrypt، الجلسات، الاستعادة وتحديد المحاولات.
- `server/database.mjs`: SQLite والترحيلات والمعاملات.
- `server/core.mjs`: إدارة الشبكات والمخزون.
- `server/commerce.mjs`: محرك الطلبات والقيود الداخلية.
- `drizzle/*.sql`: الترحيلات التنفيذية السبعة، تطبق بالترتيب وتُسجل تلقائيًا. أضف ترحيلًا جديدًا عند تعديل المخطط؛ لا تعدّل المطبق.
- المخطط الكامل معرّف في ملفات SQL؛ هذه النسخة تستخدم محرك ترحيلات مستقلًا ولا تحتاج مولد Drizzle.
- `scripts/`: إنشاء الإعدادات والمدير والنسخ والاستعادة.
- `tests/`: الاختبارات.

## التحقق الذي أُجري

نجحت 30 حالة اختبار آلية، وبناء Next.js الإنتاجي وفحص TypeScript. نجح اختبار HTTP على خادم النسخة المبنية: رفض انتحال ترويسات Sites، إنشاء حساب ودخول، شبكة وفئة واستيراد، قراءة مخزون محفوظ، قراءة الحسابات، والخروج وإلغاء الجلسة.
لم يُختبر Docker فعليًا، أو OTP، أو دفع خارجي، أو MikroTik، أو واجهات الهاتف بصريًا، أو أحمال إنتاجية. هذه نسخة تشغيل تجريبي مستقلة، وليست شهادة جاهزية مالية أو ضمان خلو من الأخطاء.

## الجديد: مختبر الربط والتسليم المزدوج

افتح «مختبر الربط» بعد الدخول. فعّل SANDBOX_ENABLED=true في .env وأعد إنشاء خدمات Compose عند الترقية من الإصدار الأول. التثبيت الجديد يضيف الإعداد تلقائيًا.
أضف كروت اختبار، ثم أنشئ طلبًا واختر سيناريو SMS. أكّد الدفع التجريبي وشغّل التسليم أو انتظر العامل. افتح معاينة المحفظة لتجربة استلام الكرت وإقراره. أعد إشعار الدفع للتحقق من عدم تكرار البيع.
في سيناريو فشل SMS مرة انتظر 30 ثانية قبل المحاولة التالية. بعد خمس محاولات فاشلة تُفتح حادثة وتتوقف القناة؛ قناة المحفظة مستقلة عنها.
البيانات في data/sandbox.sqlite منفصلة عن بيانات التشغيل؛ لا يرسل المختبر SMS حقيقية. النسخ الاحتياطي الافتراضي يغطي قاعدة التشغيل فقط؛ بيانات المختبر قابلة لإعادة الإنشاء.
راجع docs/PARTNER-API.md لعقد الربط. هذه مواصفات زد نت وليست مواصفات الكريمي أو شلن. Docker والتكاملات الخارجية ما زالت غير مختبرة هنا.

## تحديث 1.2 — المطابقة المالية

واجهة استيراد كشوف CSV موحدة لكل شبكة، مقارنة المراجع والمبالغ وحالة التحصيل، فصل الكشوف الجزئية عن الكاملة، وحفظ أسباب مراجعة الفروقات مع حماية التعارض. التفاصيل في `docs/RECONCILIATION.md`. قاعدة البيانات تُرقّى تلقائيًا؛ خذ نسخة احتياطية مع مفتاح التشفير قبل التحديث. هذا إصدار تجريبي مستقل، وليس إعلان اكتمال المنصة التجارية. تم اجتياز 33 اختبارًا آليًا والبناء واختبار HTTP؛ Docker والربط الحقيقي لم يُختبرا في هذه البيئة.

## تحديث 1.3 — توقع المخزون والمراقبة الدورية

تبويب «توقع المخزون» يحسب التغطية من المبيعات الفعلية، مع سياسة مستقلة لكل فئة وسقف للتوصيات وسجل تقييمات. خدمة `forecast-worker` المرفقة تراقب السياسات المفعلة للشبكات المعتمدة. لا تنشئ كروتًا تلقائيًا؛ ربط MikroTik ما زال مطلوبًا. راجع `docs/INVENTORY-FORECAST.md` للتثبيت وطريقة الحساب وحدود التوقع.

تم اجتياز 40 اختبارًا آليًا واختبار HTTP والبناء. فحص المتصفح لم يكتمل لعدم وجود Chromium، وتشغيل Docker لم يُختبر. عند ترقية 1.2 خذ نسخة احتياطية ومفتاح التشفير، واستبدل ملفات المصدر دون استبدال `.env` أو مجلد البيانات، ثم أعد البناء والتشغيل؛ تُطبّق ترقية قاعدة البيانات تلقائيًا.


## تحديث 1.4 — ربط MikroTik وProfiles

تبويب إعداد من ثلاث خطوات: وجهة معتمدة من المشغّل، بيانات دخول مشفرة وفحص اتصال، ثم ربط الفئات بالـProfiles. يدعم القراءة عبر HTTPS فقط؛ لا يولّد كروتًا. إعدادات الوصول والتشغيل والشهادات في `docs/MIKROTIK.md`. يبقى الموصل معطلًا افتراضيًا حتى إعداد `.env`.

التحقق: 48 اختبارًا آليًا، بناء التطبيق واختبار HTTP. يشمل اختبار نقل HTTPS محليًا؛ لا يغني عن اختبار راوتر حقيقي. عند الترقية خذ نسخة احتياطية مع مفتاحها، واحتفظ بملف `.env` والبيانات؛ تطبق ترقية قاعدة البيانات تلقائيًا. لا توجد بيانات دخول أو مفاتيح خاصة ضمن الحزمة.


## تحديث 1.5 — مركز القيادة والتحكم بالشبكات

يظهر «مركز القيادة» لحساب المدير: مؤشرات فعلية، بحث بمعرف الشبكة أو الاسم أو الهاتف أو البريد، تصفية بالمحافظة وحالة الاعتماد والتعليق، وتفاصيل المخزون والحسابات والحوادث والنشاط. التعليق يمنع الطلبات الجديدة ويحول الدفعات اللاحقة للطلبات القائمة إلى المطابقة، ويوقف المراقبة الدورية للمخزون. لا يقطع إنترنت MikroTik ولا يحذف الكروت؛ يمكن الاستئناف بسبب موثق.

دليل الإدارة في `docs/ADMIN-CENTER.md`. أُجريت 53 تجربة آلية واختبار HTTP بحساب مالك وحساب مدير، ونجح البناء. ما زال التثبيت الفعلي بـDocker والفحص البصري والربط الحقيقي بالمحافظ وSMS وتوليد الكروت خارج نطاق التحقق المنجز. جميع وظائف الإصدارات السابقة موجودة في هذه الحزمة.
